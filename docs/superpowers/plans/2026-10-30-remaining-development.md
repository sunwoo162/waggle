# 남은 제품 개발 순서

사용자의 전체 개발 진행 지시를 적용한다. 각 단계는 기능 브랜치·동작 검사·독립 리뷰·PR·CI를 거치며 완료 후 다음 단계로 이어간다. 기존 승인을 다시 묻지 않는다. 실계정·교내 실기기·실제 배포처럼 외부 환경이 필요한 결과는 코드·합성 검증과 구분한다.

## 확정한 제품 기준

- GSM 한 곳 전용. 관리자 웹과 Android·Windows 일반 사용자 앱을 구분한다.
- 등록한 AP 항목 하나에 캐릭터 하나다. 현재 AP 항목은 BSSID 하나로 식별하며 물리 장치의 여러 BSSID는 별도 등록 항목이다.
- 동일 내부 계정의 휴대폰·노트북은 수집 상태를 공유한다. 이름·이메일 일치로 서로 다른 인증 계정을 자동 병합하지 않는다.
- 사용자 도감은 캐릭터 그림·재미있는 이름·회색 미발견 중심이다. 지도·설치 위치는 관리자 웹에서만 제공한다.
- OS가 확인한 실제 연결의 BSSID와 등록 AP가 맞을 때 수집한다. 서버는 인증된 앱의 연결 보고를 받으며 이를 독립적인 무선 접속 증명으로 과장하지 않는다.
- 중앙 수집은 사용자별 발견 AP 집합이다. 학생별 이동 경로·반복 접속 시각·기기별 AP 이동 이력을 저장하지 않는다.

## 단계

- [ ] 인증된 학교 설정 배포: 활성 네트워크의 접속정보와 AP 식별자만 전달하고 지도·설치 장소는 제외. Windows 보호 캐시와 인증된 동기화 코어.
- [ ] 관리자 캐릭터·도감 동기화: AP별 이미지·별명 편집, 실제 연결 보고와 중복 없는 사용자별 수집 집합. 이미지 업로드와 안전한 정적 제공.
- [ ] Windows 실제 연결 엔진: Native Wi-Fi 어댑터, 안정성 중심 후보 판단, 사용자 동의 후 프로필 등록·연결 요청·OS 확인, 트레이·중지·실패 복구·로컬 기록. 사용자 앱 UI로 재구성.
- [ ] Android 앱: Kotlin·Compose, 코드 로그인·Keystore 보호 저장·설정 동기화, Wi-Fi suggestion·권한·허용되는 백그라운드 실행·연결 관찰·그림 도감. Gradle 검사·CI.
- [ ] 나머지 인증: DataGSM 일반 사용자·네이티브 복귀, 학교 이메일 소유 인증과 발송 어댑터. 미등록 OAuth·미설정 메일은 실제 성공으로 표시하지 않음.
- [ ] 관리자 전용 위치 시각화와 운영 마무리: 실제 도면 등록 전에는 예시 지도를 학교 도면처럼 쓰지 않음. 설정·복구·설치 안내와 교내 검증 항목 정리.

## 실제 확인에 필요한 외부 조건

DataGSM 클라이언트 등록·정확한 운영자 ID, 학교 이메일 발송 서비스와 수신 확인, 실제 학교 네트워크/AP·접속정보·도면, Android 실기기, 운영 HTTPS 서버와 서명·설치 배포 조건이 필요하다. 코드에 인증 우회·가짜 성공 모드를 추가해 이를 대체하지 않는다.
