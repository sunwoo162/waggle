# 서비스 정책

인증·권한·수집·오프라인 동작의 기준입니다.

> **확정** 도감은 실제 연결 성공이 기준입니다. 신호 발견이나 연결 시도만으로 해금하지 않습니다.

## 연결과 수집 규칙

- 현재 연결이 충분하면 유지한다.
- 상태가 지속적으로 나쁘고 더 유리한 후보가 있으면 전환을 시도하거나 OS에 후보를 제공한다.
- 전환 후에는 대기 시간과 반복 실패 후보의 일시 제외를 적용한다.
- 도감을 채우기 위해 정상 연결을 강제로 바꾸는 동작을 자동 수행하지 않는다.
- 연결 성공은 운영체제 상태로 확인한다. 요청을 보냈다는 이유로 성공 처리하지 않는다.
- 도감과 실제 AP의 매핑이 확인된 경우에만 해당 캐릭터를 해금한다.
- 같은 계정·같은 도감 항목은 한 번만 수집된다. 재연결·앱 재시작으로 새 캐릭터가 중복 생성되지 않는다.
- 도감의 미발견 표시는 게임상 미수집을 뜻한다. 기술적인 주변 네트워크 목록에서 신호가 보이는 것과 구분한다.
- Android·Windows 도감에는 지도·설치 위치·장소 탐색을 넣지 않는다. 캐릭터 그림과 별명·수집 상태를 중심으로 하고 위치 등록·지도 조회는 관리자 웹에서만 제공한다.
- 도감 공유 제안을 채택한다면 오프라인에서 얻은 수집 결과는 로컬에 보관했다가 서버에 중복 없이 동기화한다.
- 자동 관리를 중단하면 앱의 측정·연결 요청을 멈춘다. 현재 OS 와이파이 연결을 임의로 끊지 않는다.

## 인증·접속정보 흐름

- 각 로그인 경로의 결과로 이 서비스의 기기 세션을 발급한다.
- DataGSM 계정의 ADMIN 역할을 우리 서비스 관리자 권한으로 자동 연결하지 않는다.
- DataGSM에서는 활성 재학생 상태와 고유 사용자 ID를 확인한다. 졸업·자퇴 상태는 재학생과 구분한다.
- 필요 이상의 학생 정보는 로그인 기능 때문에 기본 저장하지 않는다.
- 운영자는 네트워크와 접속정보를 관리 API로 저장하고, 승인된 앱은 자신의 세션으로 필요한 설정을 받는다.
- 서버의 학교 접속정보는 복호화 가능한 암호화 저장, 전송은 TLS, 기기는 OS 보안 저장소를 사용하는 방향이다.
- 계정·코드·세션 회수는 이후 서비스 접근과 정보 갱신에 반영한다. 이미 OS에 저장된 학교 비밀번호를 네트워크 전체에서 즉시 무효화했다고 표시하지 않는다.
- 처음 로그인과 설정 다운로드에는 인터넷이 필요하다. 서버가 일시 중단되어도 이미 저장된 설정과 OS 연결을 사용할 수 있는 상태를 구분한다.

## 운영자와 일반 사용자

학교 이메일·개인 코드·DataGSM의 세 로그인 경로를 제공한다. 관리자는 운영자 한 명이다. 학교 이메일이나 DataGSM의 ADMIN 값만으로 우리 서비스의 관리자 권한을 부여하지 않는다.

개인 코드는 특정 사용자에게 발급하는 로그인 자격증명이다. 같은 사람의 휴대폰·노트북에서 사용할 수 있으며, 전체 값은 발급 시 한 번만 보여준다.

## 최초 설정과 오프라인

첫 설치·로그인·인증·설정 다운로드에는 인터넷이 필요하다. 저장된 설정이 있으면 서버가 잠시 연결되지 않아도 OS와 로컬 설정으로 연결을 지원한다. 새 로그인·코드 검증·변경된 접속정보 수신은 서버 연결 후 처리한다.

## 백그라운드 실행

Windows 창 닫기는 트레이 실행으로 이어지는 구성을 제안한다. Android는 목적에 맞는 실행 방식과 필요한 알림을 사용하고 검색·절전·제조사 정책을 검증한다. 강제 종료·기기 절전 중에도 앱이 항상 실행 중이라고 표시하지 않는다.

## 설치 위치와 개인정보

관리자 지도는 AP의 건물·층·설치 장소를 보여준다. 학생의 GPS·현재 위치·이동 경로를 중앙에 모으는 기능은 첫 버전 범위에 포함하지 않는다.

DataGSM의 고유 사용자 ID와 활성 재학생 상태를 확인한다. 이름·학년·반·번호는 목적이 있을 때 활용한다. 이메일·개인 코드·DataGSM 계정은 이름이나 이메일 일치만으로 자동 병합하지 않는 방식을 제안한다.
