# 아키텍처와 데이터

플랫폼의 책임과 서버·기기의 데이터 관계를 정리합니다.


## 구성별 책임

| 구성 | 책임 | 경계 |
| --- | --- | --- |
| 관리자 웹 | 네트워크·AP 위치·캐릭터·코드·사용자 관리 | 운영자 한 명의 인증 필요 |
| 공통 서버 | 인증·권한·설정 배포, 같은 계정의 도감 동기화 | 학교 AP를 직접 제어하는 컨트롤러가 아님 |
| Windows 앱 | 조회·연결 요청·결과 확인·트레이·도감 | 권한·어댑터·드라이버별 동작 확인 |
| Android 앱 | 네트워크 제안·상태 확인·허용된 실행·도감 | 최종 선택은 운영체제가 수행 |
| DataGSM | 기존 학교 계정 인증과 허용된 본인 정보 | 우리 서비스의 관리자 권한과 별개 |

## 정보 흐름

관리자가 등록한 학교 설정은 서버에 저장된다. 로그인한 앱이 설정을 동기화하고, 기기에서 주변 연결을 판단한다. 운영체제의 실제 연결 성공을 관찰하면 수집을 기록한다. DataGSM 로그인 성공과 학교 와이파이 연결 성공은 다른 단계이다.

## 도메인과 데이터 소유

| 개념          | 역할                                                                          |
| ------------- | ----------------------------------------------------------------------------- |
| 내부 사용자   | 서비스의 일반 사용자 또는 운영자 계정                                         |
| 인증 수단     | DataGSM ID, 검증된 학교 이메일, 개인 코드에 연결된 계정                       |
| 개인 코드     | 특정 일반 사용자에게 연결된 로그인 자격증명, 전체 원문은 발급 때만 공개       |
| 기기 세션     | 사용자·플랫폼별 로그인과 회수 상태                                            |
| 학교 네트워크 | SSID·보안 방식·접속정보·사용 여부·설정 버전                                   |
| AP            | 네트워크에 연결된 접속 장치의 식별 정보와 설치 장소                           |
| 도감 항목     | 등록 AP 하나에 대응하는 캐릭터 그림·별명·설명                                 |
| 사용자 수집   | 같은 내부 계정에서 공유하는 수집 AP 집합. 반복 방문·이동 경로는 저장하지 않음 |
| 설정 버전     | 앱이 변경된 네트워크·캐릭터 정보를 확인하는 기준                              |

서버가 관리하는 정보:
- 계정·인증 연결·기기 세션·개인 코드 상태.
- 학교 네트워크·AP 설치 위치·캐릭터 설정.
- 같은 내부 계정의 기기에서 공유하는 사용자별 수집 결과.

기기에 우선 보관하는 정보:
- 현재 신호·최근 검색 결과·품질 표본.
- 연결 시도·실패·복구 기록.
- 오프라인에 필요한 승인된 설정과 동기화 대기 중 수집 결과.

운영자의 AP 위치 화면은 설치 장치의 장소를 보여준다. 학생의 현재 위치·이동 경로를 중앙에 모으는 기능은 현재 범위에 포함하지 않는다.

> **확정** 등록 AP마다 캐릭터 하나를 두고 같은 내부 계정의 휴대폰·노트북에서 수집 상태를 공유합니다.

## 관계의 핵심

- 사용자 한 명은 여러 기기 세션을 가질 수 있다.
- 네트워크 하나에 여러 AP를 연결할 수 있다.
- 등록 AP 하나(BSSID 하나)에 캐릭터 하나를 연결한다.
- 같은 사용자·같은 도감 항목의 첫 해금은 중복 생성하지 않는다.
- DB 제품·세부 스키마·인덱스·API 경로는 구현 계획에서 정한다.
