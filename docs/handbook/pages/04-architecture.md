# 아키텍처와 데이터

플랫폼의 책임과 서버·기기의 데이터 관계를 정리합니다.


## 구성별 책임

| 구성 | 책임 | 경계 |
| --- | --- | --- |
| 관리자 웹 | 네트워크·AP 위치·캐릭터·코드·사용자 관리 | 운영자 한 명의 인증 필요 |
| 공통 서버 | 인증·권한·설정 배포, 같은 계정의 도감 동기화 | 학교 AP를 직접 제어하는 컨트롤러가 아님 |
| Windows 앱 | 조회·연결 요청·결과 확인·트레이·도감 | 권한·어댑터·드라이버별 동작 확인 |
| Android 앱 | 네트워크 제안·상태 확인·허용된 실행·도감 | 최종 선택은 운영체제가 수행 |
| DataGSM | 기존 학교 계정 인증과 허용된 본인 정보 | 우리 서비스의 관리자 권한과 별개 |

## 정보 흐름

관리자가 등록한 학교 설정은 서버에 저장된다. 로그인한 앱이 설정을 동기화하고, 기기에서 주변 연결을 판단한다. 운영체제의 실제 연결 성공을 관찰하면 수집을 기록한다. DataGSM 로그인 성공과 학교 와이파이 연결 성공은 다른 단계이다.

## 플랫폼별 약속

사용자에게 보여주는 문구는 아래 약속을 넘지 않는다.

| 항목          | Windows                                                 | Android                                                                     |
| ------------- | ------------------------------------------------------- | --------------------------------------------------------------------------- |
| 연결 방식     | Native Wi-Fi로 사용자 프로필 등록, BSSID 선호 연결 요청 | Wi-Fi suggestion 제공. 어느 네트워크에 붙을지는 OS가 결정                   |
| 사용자 문구   | "학교 Wi-Fi를 자동으로 연결하고 관리합니다"             | "학교 Wi-Fi를 휴대폰에 등록해 두고, 연결되면 도감을 채웁니다"               |
| 화면 밖 실행  | 트레이 프로세스                                         | 목적에 맞는 서비스 종류와 실행 알림. 절전·제조사 정책으로 멈출 수 있음 안내 |
| 연결 관찰     | OS 연결 상태의 SSID·BSSID·보안 방식                     | NetworkCallback·WifiInfo. 권한이 부족하면 SSID·BSSID가 가려져 수집 불가     |
| 약속하지 않음 | 모든 드라이버에서 같은 전환                             | 강제 전환, 원하는 AP 고정, 무중단 연결                                      |

Android는 위치 권한 없이 SSID·BSSID가 가려질 수 있다. 권한이 부족하면 "도감 수집을 위해 위치 권한이 필요합니다"처럼 이유와 결과를 정확히 보여주고, 가려진 값으로 수집하지 않는다.

### 7.1 Android 실현 방식

공식 문서 근거와 세부 흐름은 [Android Wi-Fi 실현 방식](../../research/2026-10-31-android-wifi-feasibility.md)에 정리했다. 요점:

- **등록**: 활성 네트워크마다 SSID 단위 suggestion을 앱 화면에서 등록하고 OS 승인을 받는다. BSSID는 지정하지 않아 OS 로밍을 막지 않는다. 등록 성공을 연결 성공으로 표시하지 않는다.
- **관찰**: NetworkCallback에 FLAG_INCLUDE_LOCATION_INFO를 붙여 연결된 Wi-Fi의 SSID·BSSID·보안 방식을 받는다. 정밀 위치 권한과 위치 설정이 필요하다. 가려진 값이면 수집하지 않는다.
- **화면 밖**: 관리를 켜면 앱 화면에서 location 유형 포그라운드 서비스를 시작하고 상시 알림을 띄운다. 백그라운드 위치 권한은 요청하지 않는다. 프로세스가 끝나면 앱을 다시 열어야 한다.
- **하지 않음**: 앱의 직접 스캔(백그라운드 30분 1회 제한), 품질 비교와 AP 전환, BSSID 지정 연결 요청, 사용자 저장 네트워크로 추가(ACTION_WIFI_ADD_NETWORKS는 앱이 이후 수정·삭제할 수 없음).
- **수집 경로 무관**: 학생이 직접 저장한 학교 Wi-Fi로 붙어도 OS가 확인한 연결이 등록 AP와 같으면 수집한다.
- **제안 기준**: 최소 Android 12(API 31), target 36. Android 11 이하는 지원하지 않는다.

## 데이터와 개인정보

### 8.1 서버가 저장하는 것

| 데이터      | 내용                                                 | 보관              |
| ----------- | ---------------------------------------------------- | ----------------- |
| 계정        | 내부 ID, 상태                                        | 계정 삭제 시까지  |
| 로그인 수단 | DataGSM 고유 ID, 검증된 이메일, 개인 코드 다이제스트 | 해제·삭제 시 제거 |
| 기기 세션   | 플랫폼, 발급·갱신·회수 상태                          | 회수·만료 후 정리 |
| 수집 집합   | (계정, AP) 쌍만                                      | 계정 삭제 시까지  |
| 학교 설정   | 네트워크·접속정보(암호화)·AP·위치·도면·캐릭터        | 운영자가 관리     |

DataGSM 응답의 학급·기숙사 등 로그인에 필요 없는 학생 정보는 저장하지 않는다.

### 8.2 기기에만 저장하는 것

- 현재 신호, 최근 검색 결과, 최근 연결 결과·실패 이유.
- 오프라인용 승인된 설정, 서버로 보내지 않은 수집 보고.
- 세션과 학교 접속정보는 OS 보안 저장소(Windows DPAPI, Android Keystore)에 보관한다.

### 8.3 수명주기 (제안)

- **졸업·자퇴**: DataGSM 신규 로그인은 거부한다. 기존 계정은 학년 말에 운영자가 비활성화·삭제할 수 있다.
- **계정 삭제**: 사용자가 내 계정에서 요청하거나 운영자가 실행한다. 로그인 수단·세션·수집 집합을 함께 삭제한다. 백업에 남은 기간은 운영 안내에 적는다.
- **회수의 한계**: 코드·세션 회수는 와글 서비스 접근을 막을 뿐, 이미 OS에 저장된 학교 Wi-Fi 비밀번호를 무효화하지 않는다. 이를 화면에서 과장하지 않는다.

> **확정** 등록 AP마다 캐릭터 하나를 두고 같은 내부 계정의 휴대폰·노트북에서 수집 상태를 공유합니다.

## 관계의 핵심

- 사용자 한 명은 여러 기기 세션을 가질 수 있다.
- 네트워크 하나에 여러 AP를 연결할 수 있다.
- 등록 AP 하나(BSSID 하나)에 캐릭터 하나를 연결한다.
- 같은 사용자·같은 도감 항목의 첫 해금은 중복 생성하지 않는다.
- 내부 계정 하나에 로그인 수단을 종류별로 하나씩 연결할 수 있다.
- DB 제품·세부 스키마·인덱스·API 경로는 구현 계획에서 정한다.
