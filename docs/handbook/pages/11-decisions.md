# 결정 기록과 남은 항목

사용자 결정, 기본 제안, 현장 검증 항목을 구분합니다.

## 확정 사항

### 2.1 사용자가 확정한 요구

| 항목                 | 확정 내용                                                                                                                                     |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 대상                 | GSM 교내 이용자, Android 휴대폰·Windows 노트북                                                                                                |
| 구현 언어            | Android Kotlin, Windows C#, 관리자 웹·서버 TypeScript                                                                                         |
| 관리자               | 사전 지정한 운영자 한 명. 관리자 화면은 웹                                                                                                    |
| 네트워크 설정        | 운영자가 실별 SSID·보안 방식·비밀번호를 등록. **연결은 SSID 기준**이며 AP(BSSID) 등록은 캐릭터용 선택 사항 (2026-11-01)                       |
| 학생 이용            | 켜기 토글 한 번 뒤로 비밀번호 입력·네트워크 선택 없이 자동 연결 (2026-11-01)                                                                  |
| 실행 방식            | 휴대폰은 OS 등록만 하고 상주하지 않음. Windows는 로그인 시 자동 실행되는 트레이 앱 (2026-11-01)                                               |
| 학생 로그인          | DataGSM / 학교 이메일 / 개인 코드. **첫 출시에 세 가지 모두 포함** (2026-10-31)                                                               |
| 학교 이메일          | 로컬 부분이 s로 시작, 도메인은 정확히 gsm.hs.kr                                                                                               |
| 개인 코드            | 한 사람에게 하나 발급, 코드만 입력해 로그인, 본인의 휴대폰과 노트북에서 사용                                                                  |
| 계정 연결            | 로그인한 상태에서 사용자가 다른 로그인 수단을 직접 추가 인증해 같은 계정에 연결 (2026-10-31)                                                  |
| 자동 병합            | 이름·이메일이 같다는 이유로 계정을 자동으로 합치지 않음                                                                                       |
| 도감                 | 캐릭터 그림·재미있는 이름·수집 상태 중심. 미발견은 회색. 사용자 앱에는 지도 없음                                                              |
| 도감 해금            | OS가 확인한 실제 연결의 SSID·BSSID·보안 방식이 등록 AP와 맞을 때만 해금                                                                       |
| 수집 단위            | **물리 AP 하나에 캐릭터 하나.** 한 장치의 여러 BSSID(밴드별)를 한 AP로 묶음 (2026-11-01)                                                      |
| 배포 범위            | 운영자가 등록한 활성 네트워크 전부를 앱에 배포. 학생에게 줘도 되는 네트워크만 등록 (2026-11-01)                                               |
| 교내 Wi-Fi 등록 요청 | 학생이 등록 안 된 교내 Wi-Fi를 앱에서 직접 요청(SSID·비밀번호·실 이름 입력). **운영자 승인 전에는 배포하지 않음**. GSM 교내 한정 (2026-11-01) |
| 배포 방식            | 교내 시범 운영은 직접 설치 파일(APK·Windows 설치 파일)로 시작. Play 스토어는 그 뒤 검토 (2026-11-01)                                          |
| 캐릭터 제작          | 운영자가 그림·별명을 등록. **그림이 없는 AP는 도감에 보이지 않고 수집되지 않음** (2026-10-31)                                                 |
| 기기 간 도감         | 같은 내부 계정의 휴대폰·노트북에서 수집 상태 공유                                                                                             |
| 관리자 위치          | 전체 AP의 건물·층·장소 조회. 지도·도면·설치 위치 관리는 관리자 웹 전용                                                                        |
| 운영자 권한          | DataGSM ADMIN 역할은 와글 관리자 권한이 아님. 사전 지정 운영자 ID만 허용                                                                      |
| 디자인               | 사용자 제공 BASE 색·타입·간격·모션 체계, 한국어 UI, 과한 장식 배제                                                                            |

### 2.2 하지 않는 것

- 여러 학교 지원과 그 확장 계획.
- 학교 밖 Wi-Fi 공유, 사용자가 연결한 Wi-Fi의 자동 수집·업로드, 기기에 저장된 비밀번호 읽기.
- 사용자 앱의 지도·도면·AP 위치 힌트.
- 학생 이동 경로, 반복 접속 시각, 기기별 AP 방문 이력의 중앙 수집.
- Android의 강제 네트워크 전환이나 무중단 연결 약속.
- 스캔·연결 요청·실패·시간 초과만으로 도감 해금.
- 도감을 채우려고 정상 연결을 강제로 바꾸는 자동 동작.
- 인증 우회나 가짜 성공 모드로 외부 조건(OAuth 등록, 메일 발송, 실제 학교 Wi-Fi)을 대신하는 것.
- 공개 순위·아이템 상점·게임 화폐, 추가 관리자, 급식·시간표, 학교 네트워크 장비와의 직접 통합.

## 배포

**2026-11-01 결정**: 교내 시범 운영까지는 직접 설치 파일로 배포한다. Play 스토어는 시범 운영 결과를 보고 검토한다. 그래서 Android 첫 버전은 스토어 심사 조건에 묶이지 않지만, 권한 이유 안내는 심사 수준으로 쓴다(나중에 스토어로 갈 때 다시 설계하지 않기 위해).

| 방식                    | 장점                              | 필요한 것·제약                                                                                     |
| ----------------------- | --------------------------------- | -------------------------------------------------------------------------------------------------- |
| 직접 설치 파일          | 심사가 없어 시범 운영을 빨리 시작 | Android "출처를 알 수 없는 앱" 허용 안내, 업데이트 직접 배포, Windows 서명 없으면 SmartScreen 경고 |
| Play 스토어(+설치 파일) | 설치·업데이트가 쉬움              | 개발자 계정, 위치·백그라운드·서비스 종류 권한 심사, 앱 내 계정 삭제 요구                           |

어느 방식이든 Windows 설치 파일 서명과 업데이트 경로, Android 서명 키 보관을 운영 안내에 포함한다.

| 날짜       | 결정                                                                                                                                             |

| 2026-11-01 | 기획 의도 재확인: 비밀번호 입력과 약한 AP의 느림 해결이 중심, 도감은 이용 동기                                                                   |
| 2026-11-01 | WARP형 제품 형태(토글 하나, 가볍게), Windows 로그인 시 자동 실행, Android 상주·위치 없이 등록 중심                                               |
| 2026-11-01 | 물리 AP 하나에 캐릭터 하나(BSSID 묶음), 등록 활성 네트워크 전부 배포, 직접 설치 파일로 시작, 시범 운영 전 Windows 현장 시험, 보안 점검 단계 추가 |
| 2026-11-01 | 연결은 SSID 기준(BSSID는 캐릭터용 선택), 교내 Wi-Fi 등록 요청 + 운영자 승인, 학교 밖 Wi-Fi 공유는 하지 않음                                      |

현재 구현:

- **main 병합**: 개발 하네스·문서 허브, DataGSM 운영자 인증, 네트워크/AP와 접속정보 암호화, 개인 코드·기기 세션(사용자·기기별 시도 제한, PR #25), 인증된 설정 배포(PR #20), AP별 캐릭터·계정 수집 API(PR #21), 공개 캐릭터만 도감·수집(PR #28), 교내 Wi-Fi 등록 요청과 운영자 요청함(PR #30).
- **Windows**: 자동 관리·그림 도감(PR #27), SSID 기준 연결(PR #29), 등록 요청 화면(PR #30), 로그인 시 자동 실행(PR #31). 합성 검사만 통과했고 실기기·교내 확인 전이다.
- **Android**: 토글 하나로 켜는 앱, 바탕화면 위젯·빠른 설정 타일, 등록 요청(PR #32). 단위 테스트·lint·빌드만 통과했고 실기기 확인 전이다.
- **미구현**: 물리 AP(BSSID 묶음) 구조, Android 도감 수집(선택), DataGSM·이메일 일반 사용자 로그인, 계정 연결, 계정 삭제, 관리자 도면·위치 시각화, 1·2차 보안 점검, 서명·설치 안내.

학교 SSID 구조·인증 방식·Android 실제 동작은 현장·기기 검증으로 확인할 항목이다. 프레임워크·API 경로·정확한 임계값은 구현 계획에서 정한다. 이 둘을 사용자에게 다시 묻는 제품 결정과 섞지 않는다.
