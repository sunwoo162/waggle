# 프로젝트 소개

무엇을 만들고, 누가 사용하며, 첫 출시에 어디까지 제공하는지 정리합니다.

> **GSM 전용** 광주소프트웨어마이스터고등학교 한 곳에서 사용하는 와이파이 자동 관리·캐릭터 수집 서비스입니다.

## 제품의 중심

**제품 형태 (2026-11-01 결정)**: Cloudflare WARP처럼 **켜기 토글 하나만 누르면 그 뒤로는 신경 쓰지 않아도 학교 Wi-Fi에 자동으로 붙는 가벼운 앱**이다. 첫 화면은 큰 토글과 상태(등록된 실 수, 마지막 갱신)만 둔다. 도감·계정 등 나머지는 뒤쪽 메뉴다.

가벼움 원칙:

- **설치에서 사용까지 3단계**: 설치 → 로그인 → 켜기. 그 뒤 학생이 할 일은 없다.
- **필요 최소 권한**: 연결 기능은 Wi-Fi 등록 권한만으로 동작한다. 위치·알림 권한은 그것이 꼭 필요한 부가 기능(Windows 실 전환, 도감)을 쓸 때만 따로 요청하고, 거절해도 연결 기능은 남는다.
- **휴대폰은 상주하지 않는다**: 켜는 순간 모든 실 Wi-Fi를 OS에 등록하고, 이후 자동 연결은 OS가 한다. 앱이 꺼져 있거나 재부팅해도 동작한다. 포그라운드 서비스·상시 알림을 쓰지 않는다. 설정 갱신은 앱을 열 때와 가벼운 주기 작업으로 한다.
- **Windows만 상주한다**: 로그인 시 자동 실행되는 트레이 앱이 실 사이 전환까지 맡는다. 스캔·판단은 낮은 빈도로 하고 속도 측정은 하지 않는다.
- **조용함**: 정상 동작 중에는 알림을 띄우지 않는다. 사용자가 해야 할 일이 있을 때만 알린다.
- **끄기는 깨끗하게**: 끄거나 로그아웃하면 와글이 등록한 Wi-Fi를 모두 지운다(연결이 끊길 수 있음을 먼저 확인).

광주소프트웨어마이스터고등학교(GSM) 전용 서비스다. 학교는 한 곳으로 고정하며 학교 선택·추가·여러 학교 운영은 계획하지 않는다.

와글은 학교 Wi-Fi의 두 가지 불편을 해결하려고 만든다. 캐릭터 도감은 이 기능을 설치하고 켜 두게 만드는 동기다.

**학교 Wi-Fi 현황 (사용자 설명, 2026-11-01, 현장 확인 대기)**: 실마다 Wi-Fi가 따로 있고 비밀번호가 실마다 조금씩 다르다. 같은 실의 비밀번호는 같지만, 실을 옮길 때마다 그 실의 비밀번호를 다시 입력해야 한다. 그래서 학생은 하루에도 여러 번 비밀번호를 입력하고, 이미 떠난 실의 약한 Wi-Fi에 붙어 있어 느려진다. 실마다 SSID가 다른지, 실의 수와 실별 AP 수, 보안 방식은 사용자가 학교에서 확인한다(9.2절).

| 불편                    | 와글의 해결                                                                                | Windows                 | Android                                                                               |
| ----------------------- | ------------------------------------------------------------------------------------------ | ----------------------- | ------------------------------------------------------------------------------------- |
| **비밀번호 입력**       | 앱이 학교 접속정보를 OS에 등록한다. 비밀번호가 바뀌어도 운영자가 고치면 앱이 다시 등록한다 | 해결                    | 해결 (처음 한 번 OS 허용)                                                             |
| **약한 AP에 붙어 느림** | 이전 실의 약한 Wi-Fi에 머물지 않게 한다                                                    | 앱이 비교하고 직접 전환 | OS 네트워크 선택에 맡김(화면 켜짐·신호 약함일 때 OS가 옮김). 앱은 개입하지 않음 (7절) |
| 학교 회선 자체의 혼잡   | 해결 대상이 아니다. 앱이 대역폭을 늘릴 수 없다                                             | -                       | -                                                                                     |

**이용 동기**: 실제로 연결한 학교 AP마다 캐릭터를 모으는 도감으로 앱을 계속 켜 둘 이유를 만든다. 도감 때문에 연결 관리 판단을 바꾸지 않는다.

우선순위는 비밀번호 없는 연결 → 약한 AP 탈출 → 도감 순이다. 위치 권한을 거절해도 비밀번호 없는 연결은 동작해야 한다.

학생은 로그인 뒤 토글을 한 번 켠다. 그 뒤에는 앱을 닫아도 자동 연결이 이어진다(휴대폰은 OS가, Windows는 트레이 앱이 맡는다). 운영자 한 명은 관리자 웹에서 학교 네트워크·AP·캐릭터·사용자 코드를 관리한다. 사용자 앱에는 지도·도면·AP 설치 위치가 없고, 이 기능은 관리자 웹에만 있다.

- 인증 우회나 가짜 성공 모드로 외부 조건(OAuth 등록, 메일 발송, 실제 학교 Wi-Fi)을 대신하는 것.

## 첫 출시 범위

"첫 출시"는 교내 시범 운영을 시작할 수 있는 상태를 뜻한다. 아래 항목이 모두 갖춰져야 한다.

### 일반 사용자 앱 (Android·Windows 공통)

- 세 가지 로그인: DataGSM, 학교 이메일 인증번호, 개인 코드.
- 내 계정 화면에서 다른 로그인 수단 추가·해제 (5절).
- 필요한 권한·네트워크 등록 안내와 동의.
- 학교 설정과 도감 동기화, 마지막 동기화 시각 표시.
- 자동 관리 시작·일시 중지와 현재 상태, 사용자가 해야 할 조치 표시.
- 실제 연결 관찰 → 등록 AP 일치 시 수집 → 조용한 알림 → 앱을 열면 컬러 해금 연출.
- 그림 도감(목록·상세), 발견 수/공개 캐릭터 수 표시.
- 기기 안에만 보관하는 최근 연결 결과와 실패 이유.
- 로그아웃 시 이 기기의 보호 저장 정보 정리.
- Windows: 트레이 실행·다시 열기·종료, 중복 실행 방지.
- Android: 켜기·끄기 토글과 OS 허용 상태 표시, 바탕화면 위젯과 빠른 설정 타일. 상주 서비스·상시 알림 없음.

### 관리자 웹

- 사전 지정 운영자 한 명의 DataGSM 인증.
- 네트워크와 접속정보 등록·수정·비활성화 (서버 암호화 저장).
- 물리 AP 등록(BSSID 여러 개 묶음)과 건물·층·설치 장소 관리, 위치 미등록 항목 확인. AP 교체 시 BSSID만 바꿔 캐릭터·수집 기록 유지.
- 도면 위 AP 설치 위치 표시와 편집.
- AP별 캐릭터 별명·소개·그림 등록, 공개 상태 확인.
- 개인 코드 발급·회수·재발급, 코드에 연결된 계정 확인.
- 일반 사용자 계정의 로그인 수단·기기 세션 조회와 회수.

### 출시 차단 조건 (외부)

세 가지 로그인을 모두 첫 출시에 넣기로 했으므로, 아래 외부 조건이 준비되기 전에는 시범 운영을 시작하지 않는다. 개발 중 운영자 본인의 점검은 개인 코드로 할 수 있지만 이를 출시로 표현하지 않는다.

- DataGSM OAuth 클라이언트 등록, 리다이렉트 URI, 정확한 운영자 ID.
- 학교 이메일 발송 서비스 설정과 gsm.hs.kr 메일함의 실제 수신 확인.
- 실제 학교 SSID·보안 방식·비밀번호·AP BSSID, 설치 장소, 도면.
- 운영 HTTPS 서버와 백업.
- 학교의 비밀번호 배포 허락.
- 직접 설치 파일 서명(Android 서명 키, Windows 코드 서명 여부)과 설치 안내 (10절).

## 핵심 사용 흐름

### 4.1 처음 사용

1. 앱을 설치하고 DataGSM, 학교 이메일, 개인 코드 중 하나로 로그인한다.
2. 앱이 필요한 권한과 이유를 안내하고, 사용자가 OS 동의 화면에서 승인한다.
3. 인증된 세션으로 학교 설정과 도감을 받는다. 처음 한 번은 인터넷(모바일 데이터 등)이 필요하다.
4. 자동 관리를 켠다.

### 4.2 평소 사용

5. 앱이나 OS가 현재 연결과 학교 네트워크 후보를 확인한다. 현재 연결이 괜찮으면 그대로 둔다.
6. OS가 등록 AP에 실제로 연결했음을 확인하면 해당 캐릭터를 처음 한 번 수집한다.
7. 새 수집이면 조용한 알림을 보내고, 사용자가 앱을 열 때 컬러 해금 연출을 보여준다.
8. 같은 계정의 다른 기기도 다음 동기화 때 같은 수집 상태를 보여준다.

### 4.3 두 번째 기기와 다른 로그인 수단

- 같은 수단으로 로그인하면 같은 계정이다. 예: 같은 개인 코드를 휴대폰과 노트북에 입력.
- 다른 수단을 쓰고 싶으면 먼저 기존 계정으로 로그인한 기기에서 그 수단을 추가 인증해 연결한다. 그 뒤에는 어느 수단으로 로그인해도 같은 계정이다.
- 연결하지 않고 다른 수단으로 로그인하면 별도 계정이 생긴다. 로그인 화면과 내 계정 화면에서 이 점을 안내한다.

DataGSM 인증 성공은 학교 Wi-Fi 연결 성공과 다른 사건이다. 앱을 켰을 때 이미 등록 AP에 연결돼 있다면 현재 연결을 실제로 확인한 뒤 수집할 수 있다. 앱이 관찰하지 않은 과거 연결을 수집으로 만들지 않는다.
