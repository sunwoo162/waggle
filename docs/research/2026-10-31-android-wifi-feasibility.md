# Android Wi-Fi 실현 방식

작성일: 2026-10-31  
근거: Android 공식 개발 문서(2026-10-31 조회). 실기기에서는 아직 확인하지 않았다. 아래에서 "문서 확인"은 공식 문서 문장으로 확인한 것이고, "실기기 확인 필요"는 문서만으로는 결론을 낼 수 없는 것이다.

## 1. 결론

Android에서 와글은 **Windows처럼 직접 AP를 고르고 연결하는 앱이 될 수 없다.** 일반 앱이 할 수 있는 것은 세 가지다.

1. **학교 Wi-Fi 정보를 OS에 제안해 둔다** (Wi-Fi suggestion). 연결 여부와 AP 선택은 OS가 한다.
2. **현재 연결을 관찰한다** (NetworkCallback). 정밀 위치 권한과 위치 설정이 켜져 있어야 SSID·BSSID가 보인다.
3. **화면 밖에서 관찰을 이어간다**. 위치 유형 포그라운드 서비스와 상시 알림이 필요하다.

기획 의도(비밀번호 입력 불편, 약한 AP의 느림)에 대입하면 다음과 같다. (2026-11-01 개정)

| 기획 의도         | Android에서 가능한 수준                                                                                                                                                |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 비밀번호 입력 0회 | **확실히 가능.** suggestion에 비밀번호를 담아 등록하고 처음 한 번 허용을 받는다. 비밀번호 변경도 재등록으로 반영된다. 위치 권한이 필요 없다                            |
| 약한 AP 탈출      | **부분적으로 가능.** BSSID를 지정하지 않아 OS 로밍이 학교 AP 전체를 후보로 쓰게 한다. 그 위에 앱이 더 나은 BSSID로 유도하는 방식(3.6절)은 실기기 확인 뒤 범위를 정한다 |
| 도감 수집         | 가능. 정밀 위치 권한과 위치 설정이 필요하다                                                                                                                            |

따라서 Android의 "자동 관리"는 다음과 같이 정의한다.

> 학교 Wi-Fi 비밀번호를 휴대폰에 등록해 두어 OS가 알아서 붙게 하고, 관리를 켜 둔 동안 약한 연결을 감지해 더 나은 학교 AP 쪽으로 유도하거나 알려 주며, 실제로 붙은 AP를 확인해 도감을 채운다.

"항상 가장 좋은 AP", 강제 전환, 무중단 연결은 약속하지 않는다.

## 3. 구현 방식

### 3.1 지원 버전

- **minSdk 31(Android 12)을 제안한다.** FLAG_INCLUDE_LOCATION_INFO, getCurrentSecurityType, 승인 상태 조회가 모두 API 31부터다. 그보다 낮은 버전을 지원하면 보안 방식 확인과 정보 가림 처리를 따로 만들어야 한다.
- targetSdk와 compileSdk는 36(Android 16). 로컬에 android-36 플랫폼을 받아 두었다.
- Android 11 이하 학생은 사용할 수 없다. 시범 운영 전에 실제 학생 기기 버전 분포를 확인한다.

### 3.2 권한

| 권한                                                      | 용도                           | 요청 시점                            |
| --------------------------------------------------------- | ------------------------------ | ------------------------------------ |
| INTERNET, ACCESS_NETWORK_STATE                            | 서버 통신, NetworkCallback     | 설치 시                              |
| ACCESS_WIFI_STATE, CHANGE_WIFI_STATE                      | suggestion 등록·조회·승인 상태 | 설치 시. 첫 등록 때 OS 승인 대화상자 |
| ACCESS_FINE_LOCATION (+ ACCESS_COARSE_LOCATION 함께 요청) | 연결한 SSID·BSSID 확인         | 관리 켜기 직전, 이유 화면 후         |
| POST_NOTIFICATIONS (Android 13+)                          | 상시 실행 알림, 새 캐릭터 알림 | 관리 켜기 직전                       |
| FOREGROUND_SERVICE, FOREGROUND_SERVICE_LOCATION           | 화면 밖 관찰                   | 설치 시                              |

요청하지 않는 권한:

- **ACCESS_BACKGROUND_LOCATION**: 포그라운드 서비스로 충분하므로 첫 출시에서 요청하지 않는다. 심사와 사용자 거부 부담이 크다.
- **NEARBY_WIFI_DEVICES**: suggestion과 연결 관찰에는 필요하지 않다. 스캔에도 위치 권한이 여전히 필요하므로 대체 효과가 없다.
- 부팅 완료 수신: 부팅 자동 시작은 미정이므로 넣지 않는다.

사용자가 "대략적 위치"만 허용하면 정밀 위치가 필요한 BSSID가 가려진다(실기기 확인 필요). 이때는 도감 수집이 안 된다고 안내하고 정밀 위치를 다시 요청할 수 있게 한다.

### 3.3 네트워크 등록

1. 로그인 후 학교 설정을 받는다.
2. 활성 네트워크마다 SSID 단위 suggestion을 만든다. BSSID는 지정하지 않는다.
   - wpa2-personal → setWpa2Passphrase, wpa3-personal → setWpa3Passphrase, open → 비밀번호 없음.
   - setCredentialSharedWithUser(false)를 제안한다. 학생이 Wi-Fi 목록에서 비밀번호를 볼 수 없게 하기 위해서다. 단, 이 경우 사용자가 직접 끊은 뒤 목록에서 다시 누르면 비밀번호를 물을 수 있다(실기기 확인 필요).
3. addNetworkSuggestions를 앱 화면에서 호출하고 승인 대화상자를 띄운다.
4. 승인 상태 리스너로 승인·대기·거절을 화면에 표시한다. 거절하면 "설정 → 특별한 앱 접근 → Wi-Fi 제어"로 안내한다.
5. 설정 버전이 바뀌면 같은 suggestion을 다시 넣어 갱신하고, 사라진 네트워크는 제거한다.
6. 앱을 열 때마다 getNetworkSuggestions로 OS에 실제로 남아 있는지 확인한다.

"등록 완료"는 OS에 제안이 들어갔다는 뜻일 뿐이다. 화면에 "연결됨"이나 "수집됨"으로 표시하지 않는다.

### 3.4 연결 관찰과 수집

1. TRANSPORT_WIFI 요청과 FLAG_INCLUDE_LOCATION_INFO로 NetworkCallback을 등록한다.
2. onCapabilitiesChanged에서 WifiInfo를 꺼낸다.
3. 아래 조건을 **모두** 만족할 때만 수집 후보로 본다.
   - SSID가 UNKNOWN_SSID가 아니고, BSSID가 null이나 02:00:00:00:00:00이 아님.
   - SSID(따옴표 제거), BSSID(소문자 정규화), 보안 방식이 공개 캐릭터가 있는 등록 AP와 정확히 일치.
   - 네트워크가 실제로 연결된 상태로 콜백이 왔음(스캔·요청·승인 사건이 아님).
4. 일치하면 계정에 묶인 Keystore 보호 대기열에 넣고 서버에 보낸다. 서버 저장 방식은 Windows와 같다(발견 AP 집합만).
5. 앱을 열었을 때 이미 연결돼 있으면 같은 절차로 현재 연결을 확인한다. 과거 연결은 만들지 않는다.

이 방식은 학생이 와글 suggestion이 아니라 직접 저장한 학교 Wi-Fi로 붙어도 수집된다. 수집 조건은 "어떤 경로로 붙었나"가 아니라 "OS가 확인한 현재 연결이 등록 AP와 같은가"이기 때문이다.

### 3.5 화면 밖 실행

| 상태                 | 동작                                                                                                                              |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 관리 켜기            | 앱 화면에서 location 유형 포그라운드 서비스를 시작하고 상시 알림 표시. 알림에 "일시 중지" 버튼                                    |
| 관리 중              | NetworkCallback 유지와 현재 신호 확인. 스캔 요청·속도 측정을 하지 않아 배터리 부담을 줄인다. 약한 연결이면 3.6절 절차             |
| 일시 중지            | 서비스와 콜백 종료. suggestion은 남기므로 OS의 자동 연결은 계속된다. 수집은 앱을 열 때만                                          |
| 서버 재확인 실패     | 관찰은 계속하되 보고는 대기열에 보관. suggestion 갱신은 정상 재확인 뒤에만                                                        |
| 권한·위치 설정 꺼짐  | 수집 중단 상태와 해결 방법을 알림과 화면에 표시                                                                                   |
| 프로세스 종료·재부팅 | 백그라운드에서 location 서비스를 다시 만들 수 없으므로, "앱을 열어 관리를 다시 켜세요" 상태로 둔다. 자동 재시작을 약속하지 않는다 |

시스템이 START_STICKY로 서비스를 다시 띄울 때 위치 접근이 유지되는지는 문서만으로 확정할 수 없다. 실기기에서 확인하고, 안 되면 위 표대로 처리한다.

### 3.6 약한 AP 대응

휴대폰은 대부분 OS가 신호가 약해지면 스스로 로밍한다. 그래서 BSSID를 지정하지 않는 것만으로도 "한 AP에 묶여 느려지는" 문제의 상당 부분을 피한다. 그 위에 앱은 아래 순서로 돕는다.

1. **감지**: 관리 중 WifiInfo의 RSSI·링크 속도가 정한 기준보다 일정 시간 계속 나쁘면 "약한 연결"로 본다. 이 값은 위치 권한 없이도 읽힌다. 임계값과 시간은 구현 계획과 현장 측정으로 정한다.
2. **후보 확인**: 정밀 위치가 있으면 getScanResults로 OS가 이미 가진 스캔 결과를 읽어, 같은 학교 SSID·보안 방식의 BSSID 중 현재보다 확실히 강한 것을 찾는다. 스캔을 새로 요청하지 않는다.
3. **유도 (실험)**: 같은 suggestion을 그 BSSID 지정으로 다시 넣어 OS가 옮기도록 유도한다. 옮겨졌거나 정한 시간 안에 안 옮겨지면 BSSID 지정을 풀어 SSID 단위로 되돌린다. 전환 뒤 대기 시간과 반복 실패 후보 제외는 Windows와 같은 원칙을 쓴다.
4. **대안**: 3이 실기기에서 효과가 없거나, 지정 중 연결이 끊기는 등 위험하면 3을 넣지 않는다. 대신 "더 가까운 학교 Wi-Fi가 있어요" 알림과 Wi-Fi 설정 패널 바로가기만 준다.
5. **해금과 분리**: 유도는 연결 품질 때문에만 한다. 새 캐릭터를 얻으려고 유도하지 않는다.

3의 효과는 문서로 확정할 수 없다. Android 단계 처음에 실기기 시험 앱으로 확인하고 결과를 이 문서 7절에 기록한 뒤 범위를 정한다.

### 3.7 로그아웃과 회수

- 로그아웃·계정 회수 시 와글이 넣은 suggestion을 제거한다. API 33 이상은 LINGER 방식으로 잠시 뒤 끊고, 그 아래는 즉시 끊길 수 있음을 확인 화면에서 먼저 알린다.
- 학생이 직접 저장한 Wi-Fi나 OS가 이미 가진 자격증명까지 지운다고 표시하지 않는다.
- Keystore의 세션·설정 캐시·보고 대기열을 함께 정리한다.

## 6. 배포 방식에 미치는 영향

배포 방식은 아직 미정이다. Play 스토어로 배포하면 위치 권한, location 유형 포그라운드 서비스 사용 목적을 심사에서 설명해야 한다. 와글의 목적은 "연결한 학교 AP 확인"이며 위치 추적이 아니라는 점, 서버에 이동 기록을 보내지 않는다는 점을 증명할 수 있어야 한다. 직접 설치 파일이면 심사는 없지만 같은 설명을 권한 안내 화면에 넣는다.

## 7. 실기기에서 확인할 항목

가장 먼저 확인할 항목 (Android 본 개발 전 시험 앱으로):

- [ ] 연결 중인 suggestion을 BSSID 지정으로 다시 넣었을 때 OS가 그 BSSID로 옮기는지, 끊김 시간은 얼마인지, 지정을 풀었을 때 정상으로 돌아오는지 (3.6절).
- [ ] 위치 권한 없이 suggestion만으로 비밀번호 없는 자동 연결이 되는지.
- [ ] 교내에서 OS 기본 로밍만으로 약한 AP에 얼마나 머무는지 (비교 기준).

그 밖의 항목:

- [ ] suggestion 승인 대화상자와 거절 후 복구 경로.
- [ ] 학생이 학교 Wi-Fi를 이미 직접 저장해 둔 경우 OS가 어느 쪽으로 붙는지, 수집은 정상인지.
- [ ] setCredentialSharedWithUser(false)일 때 사용자가 직접 끊고 다시 연결하는 흐름.
- [ ] 화면 꺼짐·절전·제조사 배터리 정책(삼성 등)에서 포그라운드 서비스와 콜백 유지 시간.
- [ ] 서비스 재시작 시 위치 정보 가림 여부.
- [ ] 대략적 위치만 허용했을 때 BSSID 가림 여부.
- [ ] WPA2/WPA3 혼합 AP에서 보고되는 보안 방식(PSK 또는 SAE)과 등록 값의 일치.
- [ ] WPA2 64자리 16진수 키를 setWpa2Passphrase가 받는지.
- [ ] 교내 AP의 밴드별·MLO BSSID가 등록 BSSID와 일치하는지.
- [ ] 관리 중 배터리 사용량.

## 8. 결정이 필요한 것

| 항목            | 제안                                                                               |
| --------------- | ---------------------------------------------------------------------------------- |
| 최소 버전       | Android 12(API 31) 이상                                                            |
| 화면 밖 실행    | 관리 중 상시 알림이 있는 포그라운드 서비스. 알림을 원하지 않으면 앱을 열 때만 수집 |
| 백그라운드 위치 | 첫 출시에서 요청하지 않음                                                          |
| 비밀번호 노출   | Wi-Fi 목록에서 비밀번호를 공유하지 않음(setCredentialSharedWithUser false)         |
| 권한 단계       | 연결은 Wi-Fi 등록 허용만으로 동작. 정밀 위치는 약한 AP 비교·도감에만 요청          |
| 약한 AP 유도    | 첫 실기기 시험 결과로 3.6절 ③(BSSID 유도) 또는 ④(알림 안내)를 선택                 |
