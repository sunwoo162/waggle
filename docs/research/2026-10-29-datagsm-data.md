# DataGSM에서 조회할 수 있는 데이터

확인일: 2026-10-29  
범위: 공개된 공식 문서와 응답 스키마 확인. 실제 학생 데이터나 인증이 필요한 API 응답은 조회하지 않았다.

## 1. OAuth 로그인한 본인 정보

기본 권한 datagsm:self_read와 로그인한 사용자의 Access Token으로 GET /userinfo를 호출하는 경로다. 학생 전체 목록을 이 로그인 응답으로 받는 구조가 아니다.

| 구분           | 문서에 나온 필드                                                                         |
| -------------- | ---------------------------------------------------------------------------------------- |
| 계정 기본 정보 | 사용자 고유 ID, 이메일, DataGSM 계정 역할, 계정 활성 상태, 학생·교사 등 연결된 대상 종류 |
| 학생 식별·소속 | 학생 ID, 이름, 학년, 반, 번호, 4자리 학번, 학과, 전공·특기 분야                          |
| 학생 추가 정보 | 성별, 기숙사 층·호실, 학생 역할, 자퇴 여부                                               |
| 선생님 정보    | 교사 ID, 이름, 이메일, 소속 부서, 설명                                                   |

학생 상세 정보는 objectType이 STUDENT인 경우 student 객체에, 교사 정보는 TEACHER인 경우 teacher 객체에 담긴다. 연결된 대상과 선택 필드에 따라 객체·필드가 null일 수 있다.

### 구현에 영향을 주는 필드 의미

- 사용자 계정 ID와 student.id는 다른 개념이다. OAuth 계정 연결에는 공급자의 사용자 계정 ID를 쓴다.
- objectType은 STUDENT, TEACHER 또는 null이다. 신규 연동에는 deprecated된 isStudent 대신 objectType을 사용한다.
- 계정 status는 PENDING 또는 ACTIVE다. ACTIVE 하나만으로 재학생을 증명하지 않는다.
- student.role에는 GENERAL_STUDENT, STUDENT_COUNCIL, DORMITORY_MANAGER, GRADUATE, WITHDRAWN이 있다. 졸업과 자퇴를 따로 구분한다.
- student.isLeaveSchool은 자퇴 여부다. false라는 이유만으로 졸업생까지 재학생으로 간주하지 않는다.
- DataGSM 계정 role의 ADMIN은 우리 와이파이 서비스의 관리자 권한을 의미하지 않는다.

근거: [OAuth 사용자 정보](https://docs.datagsm.kr/oauth/http/userinfo), [OAuth 기본 권한](https://docs.datagsm.kr/oauth).

## 2. 별도 API 키로 조회하는 OpenAPI

서비스가 발급받은 X-API-KEY와 해당 조회 범위를 사용한다. 학교 이메일이나 DataGSM으로 로그인했다는 사실만으로 아래 전체 목록을 조회할 수 있게 되는 것은 아니다.

| 데이터   | 주요 조회 항목                                                                                       | 경로                    | 권한         |
| -------- | ---------------------------------------------------------------------------------------------------- | ----------------------- | ------------ |
| 학생     | 이름·이메일·성별·학년·반·번호·학번·학과·전공·학생 역할·기숙사 층/호실·전공/자율 동아리·GitHub ID/URL | GET /v1/students        | STUDENT_READ |
| 동아리   | 이름·종류·운영 상태·설립/폐지 연도·부장·부원                                                         | GET /v1/clubs           | CLUB_READ    |
| 프로젝트 | 이름·설명·카테고리·운영 상태·시작/종료 연도·아이콘·배포 URL·동아리·참가자·저장소 URL·기술 스택       | GET /v1/projects        | PROJECT_READ |
| 급식     | 날짜·조식/중식/석식·메뉴·알레르기·열량·원산지·영양 정보·급식 인원                                    | GET /v1/neis/meals      | NEIS_READ    |
| 학사일정 | 날짜·학년도·행사명/설명·공휴일/휴업일 관련 구분·대상 학년                                            | GET /v1/neis/schedules  | NEIS_READ    |
| 시간표   | 날짜·학년도·학기·학년·반·교시·과목                                                                   | GET /v1/neis/timetables | NEIS_READ    |

각 API는 필터·페이지네이션·날짜 범위 등 지원 파라미터가 다르다. 정확한 제한은 각 엔드포인트 문서를 따른다. 일반 학생 목록에서 졸업·자퇴 상태의 학년/반/번호/학번은 null일 수 있다.

OpenAPI 학생 응답의 소속 동아리·GitHub 정보는 OAuth /userinfo의 학생 스키마와 같지 않다. OAuth 로그인만 구현하고 이러한 추가 필드까지 응답에 있다고 가정하지 않는다.

공식 문서의 목차 소개와 실제 응답 필드가 다를 때는 엔드포인트 스키마를 우선한다. 예를 들어 시간표의 확인된 필드는 교시·과목 등이며, 해당 엔드포인트 스키마에 교사명·수업 교실·실시간 학생 위치가 있다고 가정하지 않는다.

근거:

- [학생 API](https://docs.datagsm.kr/api/http/student)
- [동아리 API](https://docs.datagsm.kr/api/http/club)
- [프로젝트 API](https://docs.datagsm.kr/api/http/project)
- [급식 API](https://docs.datagsm.kr/api/http/neis/meals)
- [학사일정 API](https://docs.datagsm.kr/api/http/neis/schedules)
- [시간표 API](https://docs.datagsm.kr/api/http/neis/timetables)

## 3. 데이터 변경을 받는 Event

수신 URL을 등록하면 다음 변경을 외부 서버로 받을 수 있다.

- student.updated: 학생 정보·졸업·자퇴·역할 등 변경
- club.updated: 동아리 생성·수정·삭제
- project.updated: 프로젝트 생성·수정·삭제

페이로드에는 변경 전과 후 정보가 들어간다. HTTP POST와 서명 검증을 사용한다. 재시도 후 영구 손실될 수 있다는 문서상 제약이 있으므로, 권한 회수에 사용한다면 로그인 시 재확인 등 정합성 점검도 필요하다. Event 연동은 가능한 후속 선택지이며 현재 첫 버전 구현 요구에 추가하지 않는다.

근거: [Event](https://docs.datagsm.kr/event).

## 4. 조회 조건과 운영 특성

- OpenAPI는 별도 키와 범위가 필요하며 요청량 제한이 있다.
- 문서상 API 키는 30일마다 갱신해야 한다. 실제 연동 시 현재 발급 정책을 다시 확인한다.
- DataGSM 가입 및 개인정보 처리약관 동의가 없는 학생의 데이터는 OpenAPI 응답에서 제공하지 않는다고 안내한다. 목록이 학교 전체 학생을 빠짐없이 포함한다고 가정하지 않는다.
- 서버의 API 키는 학생 앱에 공통으로 배포하지 않고 서버에서 필요한 요청을 중계하는 구성을 제안한다.
- 조회 가능한 스키마와 실제 데이터의 채워짐·최신성은 다르다. 인증 후 선택 필드의 null과 변경 상태를 확인한다.

근거: [OpenAPI 개요](https://docs.datagsm.kr/api).

## 5. 와이파이 서비스에서의 활용 제안

현재 핵심 기능에 필요한 최소값은 DataGSM 사용자 고유 ID와 학생/계정 상태다. 운영자·사용자 화면에서 본인을 식별하는 목적이라면 이름을 추가로 사용할 수 있다. 관리자 목록에서 반별 구분이 실제로 필요할 때 학년·반·번호를 추가할 수 있다. 후자의 표시 기능은 제안이며 아직 확정한 요구가 아니다.

재학생 확인에는 objectType, 계정 status, student.role과 자퇴 상태를 함께 확인한다. 성별·기숙사 호실·전공 분야는 현재 연결 기능에 필요하지 않으므로 기본 저장 대상으로 제안하지 않는다.

학교 데이터로 서비스를 확장하기로 결정하면 급식·시간표 카드, 학교 일정 안내, 동아리/프로젝트 소개 등을 검토할 수 있다. 이번 조사는 데이터 제공 가능 범위를 확인한 것이며 이러한 기능을 구현하기로 합의한 것은 아니다.

기숙사 호실과 학급은 현재 기기의 물리적 위치를 뜻하지 않는다. AP 선택은 기기에서 관찰한 신호와 연결 이력에 근거한다.

공식 문서의 현재 API 목록에서 와이파이 SSID·AP 목록·비밀번호·실시간 혼잡도 제공은 확인하지 못했다. 이러한 접속정보는 관리자가 등록하고, 기기별 품질은 앱이 확인하는 기존 구성을 유지한다.
