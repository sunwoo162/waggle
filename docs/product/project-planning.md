# 와글 프로젝트 기획 총괄표

작성일: 2026-10-29  
상태: 운영자·학교 네트워크/AP·개인 코드·캐릭터 관리와 Windows 인증·자동 관리·그림 도감 구현. DataGSM 미등록으로 실제 계정 연동·교내 Wi-Fi는 검증 전이다. Android 앱·학교 이메일 인증은 후속이다.  
상세 요구: [제품 기획서](../superpowers/specs/2026-10-29-campus-wifi-design.md)  
디자인 기준: [BASE 적용안](../design/design-system.md)

## 1. 제품의 중심

광주소프트웨어마이스터고등학교(GSM) 전용 서비스다. 학교는 한 곳으로 고정하며 학교 선택·추가·여러 학교 운영은 계획하지 않는다.

학생이 처음 로그인·권한 설정 후 자동 관리를 켜두면, 다른 작업을 하는 동안 교내 와이파이를 관리한다. 운영자는 학교 네트워크와 AP 위치를 웹에서 관리한다. 실제로 연결에 성공한 와이파이가 캐릭터 도감에 수집돼 사용자가 재미를 느끼게 한다. 사용자 도감은 그림을 모아 보는 화면이며 지도·도면·AP 설치 위치 기능은 관리자 웹에만 둔다.

화면 목록과 시안은 준비돼 있다. 기획 마무리에는 기능의 동작 조건, 계정과 데이터의 관계, 첫 출시 범위, 플랫폼별 실제 가능 범위와 검증 기준이 필요하다. 세부 화면 디자인은 아래 규칙을 바탕으로 개발하면서 다듬는다.

## 3. 첫 출시 범위

### 일반 사용자 앱

- 세 가지 로그인, 초기 권한 안내, 학교 설정 동기화.
- 현재 연결과 자동 관리 상태, 필요한 사용자 조치 표시.
- 주변 학교 네트워크 비교, 결과 확인, 가능한 범위의 복구.
- 백그라운드 실행 상태와 명시적인 일시 중지·종료.
- 실제 연결 성공에 따른 캐릭터 해금, 도감·상세·수집 알림.
- 로컬 연결 기록, 설정·내 계정·문제 해결.
- Windows 트레이와 Android에 필요한 실행 알림.

### 관리자 웹

- 사전 지정한 관리자 한 명의 인증.
- 네트워크와 접속정보 등록·수정·비활성화.
- 전체 AP의 식별 정보·건물·층·설치 장소 관리와 위치 조회.
- 캐릭터 별명·그림·설명과 와이파이 매핑 관리.
- 일반 사용자·기기 세션·서비스 접근 상태 조회.
- 개인 코드 발급·회수·재발급.

### 첫 출시 이후 검토

추가 관리자, 급식·시간표, 공개 순위·아이템 상점, 계정 통합, 학교 네트워크 제어 장비와의 직접 통합은 후속 검토 항목이다. 학교는 이후에도 GSM 한 곳으로 고정한다. 화면 34종은 여러 인증·상태·플랫폼 표현을 정리한 목록이며 각 화면을 별도 시스템으로 개발하는 단위는 아니다.

## 4. 나머지 기획에 대한 기본 제안

아래는 아직 사용자 확정 요구와 구분되는 제안이다. 전체 기획 검토 때 함께 확인할 수 있게 묶어둔다.

| ----------- | ---------------------------------------------------------- | ---------------------------------------------------------------- |
| 계정 연결   | 로그인 경로별 외부 ID를 구분하고 자동 병합하지 않음        | 이름·이메일 일치만으로 다른 계정의 도감을 합치지 않음            |
| 운영자 인증 | DataGSM 인증 후 사전 지정한 운영자 ID 한 개만 관리자 허용  | 학생 로그인 연동을 활용하면서 관리자 권한은 서비스가 별도로 결정 |
| 웹·서버     | TypeScript를 주 언어로 제안                                | 관리자 화면과 API에 같은 언어 사용                               |
| 데이터 저장 | 관계형 데이터베이스                                        | 계정·세션·네트워크·AP·캐릭터의 관계와 중복 수집 방지에 사용      |
| 자동 시작   | 첫 버전은 사용자가 앱에서 시작한 관리 세션을 기준으로 검증 | 부팅 자동 실행·강제 종료 후 재시작은 OS 조건 확인 후 별도 선택   |
| 품질 검사   | 가벼운 상태 확인, 필요한 경우의 제한된 데이터 전송 검사    | 후보 전부의 속도를 반복 측정하는 부담 감소                       |

구체 프레임워크·데이터베이스 제품·호스팅·메일 제공업체는 구현 계획에서 정한다. 이 선택을 위해 사용자에게 제품의 세부 동작을 다시 물을 필요는 없다.

## 5. 핵심 사용 흐름

1. DataGSM, 학교 이메일 또는 개인 코드로 로그인한다.
2. 필요한 권한·네트워크 등록 동의를 완료한다.
3. 학교 네트워크와 캐릭터 설정을 받는다.
4. 자동 관리를 켠다.
5. 앱·OS가 현재 연결과 후보를 확인하고 적절한 연결을 선택한다.
6. 등록된 학교 AP에 실제 연결 성공한 것이 확인되면 해당 캐릭터의 첫 수집을 기록한다.
7. 새 수집이면 조용한 알림을 주고, 사용자가 열 때 컬러 해금 연출을 보여준다.
8. 다음 이용에서는 저장된 설정과 기록을 이어서 활용한다.

DataGSM 인증 성공은 학교 와이파이 연결 성공과 다른 사건이다. 주변에서 SSID가 보이는 것, 연결 요청을 보낸 것, 연결에 실패한 것은 도감 해금 사건이 아니다. 앱을 켰을 때 이미 연결되어 있다면 현재 연결을 실제로 확인한 뒤 수집 대상으로 처리할 수 있다. 앱이 관찰하지 않은 과거 연결 이력을 임의로 만들어 수집하지 않는다.

## 6. 연결과 수집 규칙

- 현재 연결이 충분하면 유지한다.
- 상태가 지속적으로 나쁘고 더 유리한 후보가 있으면 전환을 시도하거나 OS에 후보를 제공한다.
- 전환 후에는 대기 시간과 반복 실패 후보의 일시 제외를 적용한다.
- 도감을 채우기 위해 정상 연결을 강제로 바꾸는 동작을 자동 수행하지 않는다.
- 연결 성공은 운영체제 상태로 확인한다. 요청을 보냈다는 이유로 성공 처리하지 않는다.
- 도감과 실제 AP의 매핑이 확인된 경우에만 해당 캐릭터를 해금한다.
- 같은 계정·같은 도감 항목은 한 번만 수집된다. 재연결·앱 재시작으로 새 캐릭터가 중복 생성되지 않는다.
- 도감의 미발견 표시는 게임상 미수집을 뜻한다. 기술적인 주변 네트워크 목록에서 신호가 보이는 것과 구분한다.
- Android·Windows 도감에는 지도·설치 위치·장소 탐색을 넣지 않는다. 캐릭터 그림과 별명·수집 상태를 중심으로 하고 위치 등록·지도 조회는 관리자 웹에서만 제공한다.
- 오프라인에서 OS가 확인한 수집 결과는 계정에 묶인 OS 보호 저장소에 보관했다가 서버에 중복 없이 동기화한다. 같은 내부 계정의 기기끼리 수집 상태를 공유하며 로그인 수단이 다른 계정을 자동 병합하지 않는다.
- 자동 관리를 중단하면 앱의 측정·연결 요청을 멈춘다. 현재 OS 와이파이 연결을 임의로 끊지 않는다.

## 7. 도메인과 데이터 소유

| 개념          | 역할                                                                          |
| ------------- | ----------------------------------------------------------------------------- |
| 내부 사용자   | 서비스의 일반 사용자 또는 운영자 계정                                         |
| 인증 수단     | DataGSM ID, 검증된 학교 이메일, 개인 코드에 연결된 계정                       |
| 개인 코드     | 특정 일반 사용자에게 연결된 로그인 자격증명, 전체 원문은 발급 때만 공개       |
| 기기 세션     | 사용자·플랫폼별 로그인과 회수 상태                                            |
| 학교 네트워크 | SSID·보안 방식·접속정보·사용 여부·설정 버전                                   |
| AP            | 네트워크에 연결된 접속 장치의 식별 정보와 설치 장소                           |
| 도감 항목     | 등록 AP 하나에 대응하는 캐릭터 그림·별명·설명                                 |
| 사용자 수집   | 같은 내부 계정에서 공유하는 수집 AP 집합. 반복 방문·이동 경로는 저장하지 않음 |
| 설정 버전     | 앱이 변경된 네트워크·캐릭터 정보를 확인하는 기준                              |

서버가 관리하는 정보:
- 계정·인증 연결·기기 세션·개인 코드 상태.
- 학교 네트워크·AP 설치 위치·캐릭터 설정.
- 같은 내부 계정의 기기에서 공유하는 사용자별 수집 결과.

기기에 우선 보관하는 정보:
- 현재 신호·최근 검색 결과·품질 표본.
- 연결 시도·실패·복구 기록.
- 오프라인에 필요한 승인된 설정과 동기화 대기 중 수집 결과.

운영자의 AP 위치 화면은 설치 장치의 장소를 보여준다. 학생의 현재 위치·이동 경로를 중앙에 모으는 기능은 현재 범위에 포함하지 않는다.

## 8. 인증·접속정보 흐름

- 각 로그인 경로의 결과로 이 서비스의 기기 세션을 발급한다.
- DataGSM 계정의 ADMIN 역할을 우리 서비스 관리자 권한으로 자동 연결하지 않는다.
- DataGSM에서는 활성 재학생 상태와 고유 사용자 ID를 확인한다. 졸업·자퇴 상태는 재학생과 구분한다.
- 필요 이상의 학생 정보는 로그인 기능 때문에 기본 저장하지 않는다.
- 운영자는 네트워크와 접속정보를 관리 API로 저장하고, 승인된 앱은 자신의 세션으로 필요한 설정을 받는다.
- 서버의 학교 접속정보는 복호화 가능한 암호화 저장, 전송은 TLS, 기기는 OS 보안 저장소를 사용하는 방향이다.
- 계정·코드·세션 회수는 이후 서비스 접근과 정보 갱신에 반영한다. 이미 OS에 저장된 학교 비밀번호를 네트워크 전체에서 즉시 무효화했다고 표시하지 않는다.
- 처음 로그인과 설정 다운로드에는 인터넷이 필요하다. 서버가 일시 중단되어도 이미 저장된 설정과 OS 연결을 사용할 수 있는 상태를 구분한다.

## 9. 플랫폼별 출시 조건

Windows는 Native Wi-Fi API를 이용한 조회·프로필 연결 요청과 트레이 실행을 검증한다. 권한·드라이버별 차이, 창 닫기·재열기와 관리 프로세스 중복 실행을 확인한다.

Android는 일반 설치 앱의 권한 범위에서 네트워크 제안을 제공한다. 화면을 내렸을 때의 실행, 실행 알림, 화면 꺼짐·절전·제조사 정책, 검색 제한과 연결 성공 관찰을 실제 기기에서 확인한다. 앱이 원하는 순간의 AP 강제 전환을 출시 약속으로 넣지 않는다.

학교 현장에서는 여러 SSID인지 같은 SSID의 여러 AP인지, 공유 암호 인증인지 추가 로그인 화면이 있는지, AP별 BSSID와 실제 설치 장소가 어떤지 확인한다. 학교의 외부 IP가 같다는 이유만으로 끊김 없는 내부 로밍을 가정하지 않는다.

## 10. 기술 검증과 개발 진행 방향

이 목록은 기능 기획의 진행 방향이며, 상세 구현 작업표는 기획 검토 후 작성한다.

1. 학교 네트워크와 실제 기기에서 검색·연결·권한·백그라운드 실행·연결 성공 관찰을 검증한다.
2. 공통 인증·관리자 네트워크/AP 등록·설정 배포의 흐름을 만든다.
3. Windows에서 설정 받기 → 자동 관리 → 연결 성공 → 도감 해금의 흐름을 완성한다.
4. 같은 서버·도감 규칙을 Android의 허용 범위에 맞춰 연동한다.
5. BASE 디자인 시스템으로 각 플랫폼 화면을 개발하면서 통일한다.
6. 실패·오프라인·회수·동기화·중복 수집과 실제 개선 효과를 검증하고 교내 소규모 사용을 거친다.

DataGSM 클라이언트 등록·콜백 조건, 실제 학생 계정 검증, 메일 수신 가능 여부, 호스팅과 비밀값 준비는 연동 시 필요한 외부 조건이다. 현재 단계에서 실제 서비스 계정 생성·운영 배포를 실행한 것은 아니다.

## 11. 기획에서 정하는 성공 기준

- 최초 설정 이후 학생이 각 와이파이 비밀번호를 직접 입력하지 않는다.
- 세 가지 로그인 경로가 각각 일반 사용자 세션으로 연결된다.
- 앱 화면 밖에서 가능한 자동 관리 범위가 실제 상태와 일치하게 표시된다.
- 신호 발견·연결 요청·실패만으로 캐릭터가 해금되지 않고 실제 연결 확인 때 해금된다.
- 동일 계정의 동일 캐릭터가 중복 수집되지 않는다.
- 두 기기의 수집 결과가 같은 내부 계정에서 일치한다.
- 관리자는 주변에 보이지 않는 등록 AP도 조회하고 위치 미등록 항목도 확인할 수 있다.
- 설정 변경·코드 회수·서버 장애·권한 거절 시 사용자에게 정확한 상태와 다음 행동을 안내한다.
- 동일 기기·비슷한 경로에서 기본 OS 동작과 비교해 수동 전환·연결 실패·응답 지연·반복 전환·측정량·배터리 부담을 확인한다.
- 실제로 측정하지 않은 최고 속도·전체 AP 실시간 혼잡도·무중단 연결을 성공 지표로 표시하지 않는다.

## 12. 남은 결정과 현재 위치

2026-10-30 사용자 결정으로 등록 AP마다 캐릭터 하나, 같은 내부 계정의 기기 간 도감 공유를 확정했다. 현재 AP 한 항목은 BSSID 하나이며 물리 장치의 여러 BSSID를 임의로 합치지 않는다. 남은 제품 제안은 첫 출시의 부팅 자동 시작 범위이며 첫 출시의 필수 조건으로 두지 않는 기본안을 유지한다.

학교 SSID 구조·인증 방식·실제 Android 동작은 현장·기기 검증으로 확인할 항목이다. 프레임워크·DB·API 경로·정확한 임계값·알림 구현은 구현 계획에서 정할 항목이다. 이 세 종류를 섞어 같은 수준의 사용자 질문으로 취급하지 않는다.

운영자 인증·네트워크/AP·개인 코드 관리와 Windows 코드 로그인·보호 세션 저장을 구현했다. 인증된 학교 설정 배포 API와 Windows의 검증·계정별 보호 캐시 코어, 관리자 캐릭터 편집·계정 수집 API를 추가했다. 합성 서버·계정으로 확인했으며 앱 화면의 설정 동기화·OS 프로필 설치·연결 관찰·사용자 도감에는 아직 연결하지 않았다. 학교 이메일·DataGSM 네이티브 복귀·Wi-Fi 자동 연결·Android는 후속 구현과 현장 검증이 필요하다.
