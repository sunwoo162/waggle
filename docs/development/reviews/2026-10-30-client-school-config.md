# 학교 설정 배포 검토

범위: 710bf605..ae1f10a의 서버 설정 배포와 Windows 보호 캐시. 기능 작성과 분리된 읽기 전용 리뷰 한 건을 수행했다. 리뷰어는 서버 5개·기존 Windows 23개 검사를 직접 통과시켰다.

## 발견과 처리

Important 두 건을 채택해 한 번의 수정 단계에서 처리했다.

1. 설정을 받은 뒤 비동기 캐시 읽기·저장 중 로그아웃이 완료돼도 이전 계정의 접속정보를 반환할 수 있었다. 설정 검증·캐시 저장·게시까지 MemberSession의 인증 잠금 안에서 실행하도록 바꿨다. 지연된 읽기·저장 각각에서 로그아웃이 직렬화되는 회귀 검사를 RED → GREEN으로 확인했다.
2. 계정 확인 직후 접근 토큰이 만료되면 설정 요청의 401이 갱신 가능한 세션도 삭제했다. 계정 확인과 설정 요청 전체에 한 번의 갱신·재시도 예산을 적용했다. 설정 요청에서만 만료, 계정 확인에서 이미 갱신, 재시도 거부의 검사를 추가했다. 거부된 세션은 계속 제거한다.

수정 후 Windows 28개·Release 빌드·공백 검사 통과. Critical·Minor 발견은 없었다. 재리뷰는 수행하지 않았다. 기존 Windows 인증 검토에서 보류한 실제 HTTP 리디렉션·길이 없는 큰 JSON 검사는 이 변경의 실제 loopback 통합 검사로 보완했다.

## 범위 판단

리뷰어가 판단에서 제외한 앱 화면·캐시 Clear 연결·오프라인 정책·OS 프로필 설치는 다음 클라이언트 단계로 유지했다. 기획과 운영 안내에 현재 한계를 명시했다. 실제 학교 연결·사람 계정·운영 배포는 합성 검사로 대체할 수 없어 미검증으로 유지했다.

리뷰어는 GitHub CI와 별도 Node/.NET 통합 실행을 반복하지 않았다. 구현자는 실제 서비스와 HTTP, .NET·DPAPI의 합성 통합 결과를 확인했고 PR 현재 커밋의 CI를 별도로 확인한다. UI 변경이 없는 단계이며 학교 설정·호스트 Wi-Fi를 조작하지 않았다.
